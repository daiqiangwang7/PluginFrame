# PluginFrame 框架使用说明

本文档说明当前 Qt5 微内核插件框架的使用方式、已有功能和插件开发约定。

## 1. 框架定位

PluginFrame 是一个基于 Qt 5.15.2 和 CMake 的插件式开发框架原型。框架采用微内核思路：

- 宿主程序只负责插件加载、生命周期管理、窗口承载、主题和公共服务。
- 具体业务功能通过插件扩展。
- 插件分为带界面的视图插件和无界面的后台服务插件。

当前框架适合作为后续业务系统的基础骨架，后续可以继续扩展菜单、工具栏、日志中心、设置中心、权限控制、插件市场和热更新等能力。

## 2. 当前已有功能

### 2.1 插件接口

接口位于 `framework/` 目录：

- `IPlugin`：基础插件接口，定义 `initialize()`、`start()`、`stop()`、`name()`。
- `IViewPlugin`：视图插件接口，继承 `IPlugin`，额外提供 `widget()` 和 `displayName()`。
- `IServicePlugin`：服务插件接口，继承 `IPlugin`，用于后台服务类插件。
- `IPluginContext`：插件运行上下文，向插件提供框架公共能力。

### 2.2 插件生命周期管理

`PluginManager` 负责插件生命周期，当前支持状态：

- `Loaded`：已扫描并读取元数据。
- `Initialized`：已完成初始化。
- `Started`：已启动运行。
- `Stopped`：已停止。
- `Disabled`：已禁用。
- `Failed`：加载、初始化或依赖检查失败。

宿主退出时会停止已启动插件。

### 2.3 插件依赖与加载顺序

插件可在 `metadata.json` 中声明依赖：

```json
{
  "dependencies": [
    "com.pluginframe.time-service"
  ]
}
```

加载规则：

- 宿主先扫描全部插件元数据。
- 再按依赖关系启动插件。
- 同一依赖层级中，服务插件优先于视图插件启动。
- 依赖缺失、依赖插件未启动或循环依赖时，插件会被标记为 `Failed`。

### 2.4 内部通信

框架提供 `MessageBus`，插件可通过 `IPluginContext::messageBus()` 发布和订阅消息。

示例：

```cpp
m_context->messageBus()->publish(QStringLiteral("hello.clicked"),
                                 {{QStringLiteral("plugin"), name()}});
```

当前示例中：

- `TimeServicePlugin` 每秒发布 `time.tick`。
- `HelloPlugin` 订阅 `time.tick` 并更新界面显示。

### 2.5 能力注册中心

框架提供 `CapabilityRegistry`，插件可通过 `IPluginContext::capabilityRegistry()` 注册能力。

能力类型可用于描述：

- `view`：视图窗口。
- `service`：后台服务。
- `command`：命令入口。
- `settings`：设置页。

示例：

```cpp
m_context->capabilityRegistry()->registerCapability({
    QStringLiteral("com.pluginframe.hello"),
    QStringLiteral("hello.view"),
    QStringLiteral("view"),
    QStringLiteral("你好插件视图"),
    QStringLiteral("HelloPlugin")
});
```

能力注册中心是后续菜单、工具栏、右侧抽屉、设置中心动态生成的基础。

### 2.6 插件私有配置

框架提供 `PluginSettings`，插件可通过 `IPluginContext::pluginSettings()` 读写私有配置。

默认配置保存路径：

```text
config/plugins/<pluginId>.ini
```

示例：

```cpp
const QString pluginId = QStringLiteral("com.pluginframe.hello");
m_context->pluginSettings()->setValue(pluginId,
                                      QStringLiteral("ui/greeting"),
                                      QStringLiteral("你好，来自视图插件！"));
```

当前示例：

- `HelloPlugin` 使用 `ui/greeting` 配置欢迎文案。
- `TimeServicePlugin` 使用 `timer/intervalMs` 配置定时器间隔。

### 2.7 多区域窗口管理

框架提供 `WindowManager`，不再依赖单一 `QTabWidget`。

当前支持窗口区域：

- `Central`：中心工作区。
- `LeftDock`：左侧停靠区。
- `RightDock`：右侧停靠区。
- `BottomDock`：底部停靠区。
- `Floating`：浮动窗口。

插件视图默认注册到中心工作区。

### 2.8 插件诊断页

主程序内置插件诊断页，当前显示：

- 插件名称。
- 插件类型。
- 插件版本。
- 插件依赖。
- 生命周期状态。
- 插件路径。
- 错误信息。

该页面用于排查插件加载失败、依赖失败和元数据错误。

### 2.9 界面与主题

当前 UI 特性：

- 自绘标题栏。
- 自绘最小化、最大化、关闭按钮。
- 自绘皮肤切换按钮。
- 右侧居中抽屉把手。
- 右侧抽屉入口：总览、插件、服务、日志、设置。
- 标题栏和主界面之间有明确分割线。
- 底部状态栏显示主题、插件数量、服务数量和时间。
- 默认中文界面。

当前内置主题：

- `cyber-dark`：深色赛博朋克主题。
- `cyber-light`：浅色赛博朋克主题。

主题文件：

```text
themes/cyber-dark.qss
themes/cyber-light.qss
```

## 3. 如何构建运行

在项目根目录执行：

```powershell
cmake -S . -B build
cmake --build build --config Debug
```

运行宿主程序：

```powershell
.\build\bin\Debug\PluginHost.exe
```

插件构建后会复制到：

```text
build/bin/plugins/Debug/
```

宿主运行时会扫描应用目录下的 `plugins` 目录。

## 4. 如何开发一个视图插件

视图插件需要继承 `QObject` 和 `IViewPlugin`。

基本步骤：

1. 新建插件目录，例如 `plugins/MyViewPlugin/`。
2. 编写插件类，继承 `IViewPlugin`。
3. 使用 `Q_INTERFACES(IPlugin IViewPlugin)`。
4. 使用 `Q_PLUGIN_METADATA(IID IViewPlugin_iid FILE "metadata.json")`。
5. 在 `initialize()` 中创建 QWidget。
6. 在 `widget()` 中返回主界面。
7. 在 `displayName()` 中返回界面标题。
8. 编写 `metadata.json`。
9. 添加插件目录的 `CMakeLists.txt`。
10. 在根目录 `CMakeLists.txt` 中添加 `add_subdirectory()`。

最小元数据示例：

```json
{
  "id": "com.pluginframe.my-view",
  "name": "MyViewPlugin",
  "displayName": "我的视图",
  "version": "1.0.0",
  "type": "view",
  "enabled": true
}
```

如果依赖服务插件：

```json
{
  "dependencies": [
    "com.pluginframe.time-service"
  ]
}
```

## 5. 如何开发一个服务插件

服务插件需要继承 `QObject` 和 `IServicePlugin`。

服务插件没有 UI，适合做：

- 定时任务。
- 数据采集。
- 后台通信。
- 本地缓存。
- 设备连接。
- 业务服务。

基本步骤：

1. 新建插件目录，例如 `plugins/MyServicePlugin/`。
2. 编写插件类，继承 `IServicePlugin`。
3. 使用 `Q_INTERFACES(IPlugin IServicePlugin)`。
4. 使用 `Q_PLUGIN_METADATA(IID IServicePlugin_iid FILE "metadata.json")`。
5. 在 `initialize()` 中创建后台对象。
6. 在 `start()` 中启动服务。
7. 在 `stop()` 中停止服务并释放资源。
8. 通过 `MessageBus` 对外发布消息。

最小元数据示例：

```json
{
  "id": "com.pluginframe.my-service",
  "name": "MyServicePlugin",
  "displayName": "我的服务",
  "version": "1.0.0",
  "type": "service",
  "enabled": true
}
```

## 6. 应用 XML 配置

宿主启动时读取：

```text
config/app.xml
```

当前支持：

- 默认主题。
- 插件启用状态。
- 视图插件注册区域。

示例：

```xml
<application>
  <theme default="cyber-dark"/>

  <plugins>
    <plugin id="com.pluginframe.hello" enabled="true" area="central"/>
    <plugin id="com.pluginframe.time-service" enabled="true"/>
  </plugins>
</application>
```

`area` 支持：

- `central`
- `leftDock`
- `rightDock`
- `bottomDock`
- `floating`

## 7. 当前示例插件

### 7.1 HelloPlugin

类型：视图插件。

功能：

- 显示中文插件界面。
- 订阅宿主状态消息。
- 订阅时间服务消息。
- 点击按钮发布 `hello.clicked` 消息。
- 注册 `view` 能力。
- 读取和保存 `ui/greeting` 配置。

### 7.2 TimeServicePlugin

类型：服务插件。

功能：

- 启动后台定时器。
- 每秒发布 `time.tick` 消息。
- 注册 `service` 能力。
- 读取和保存 `timer/intervalMs` 配置。

## 8. 当前目录结构

```text

src/                       宿主程序源码

plugins/TimeServicePlugin/ 示例服务插件
themes/                    深色和浅色主题
config/                    应用 XML 配置
docs/                      项目文档
```
